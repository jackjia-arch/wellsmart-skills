# Well Smart AI Design Workflow

This skill turns a project brief into a mature, sign-off-ready, all-discipline design package with one person operating the AI, then keeps the same project record alive through manual Revit production, procurement, construction and operations. People decide at gates and read one high-risk table; everything else — layouts, calculations, drawings, models, reviews, packages, uploads — is produced by the AI from a single design database and recorded in one growing project knowledge base. External consultants are engaged only when the AI package is mature (S9), to verify, adopt and sign. The AI design target is a mature package in 4–8 weeks; consultant response, statutory approvals, construction and handover run on their own programmes.

Read this file fully, then open the reference file for the stage or task at hand. Do not load every reference at once.

## Hard rules

1. **Single source of truth, with disciplined write-back.** One project repository: `brief/`, `site/`, `db/` (design database, JSON), `calcs/`, `drawings/`, `model/`, `thermal/`, `reports/`, `issues/`, `reviews/`, `decisions.md`, `catalogue.json`. Drawings, IFC, calc books, BQ and RFQ packs are generated from the DB. Manual detailing (Revit, drafting, site changes) may edit outputs, but every manual version is diffed against the previous one: annotation-only changes are recorded as "no design change" and nothing is rerun; a design change (dimension, load, material, equipment, interface, control, performance, new anchors / supports / penetrations) is written back to the DB by stable element ID and only the affected calcs, sheets, models and BQ lines are regenerated. Generators never silently overwrite manual detailing (`references/db-schema.md`, overrides register and id-map). Engineering source files stay in the repository; the project knowledge base (catalogue + immutable originals) records file relationships and states and is always merged into — items are added or revised by ID, never replaced by a new folder.
2. **If it can be calculated, a script calculates it.** Velocities, pressure drops, voltage drop, demand, loads, egress widths, tank volumes: run the calculation, show intermediate numbers. The language model interprets codes, chooses options, writes assumptions and reviews logic; it does not "estimate" a number a script can compute. The company checks library is the most valuable part of the skill.
3. **Every number has a calc ID.** Format `<DISC>-<NNN>`. Each calc is one page in the calc register: inputs, method, governing clause (standard, year, clause, digest record id), result, check against limit, status, date, script version. Drawings carry a key design-data box, an assumptions box and calc IDs — not the full calculation.
4. **Company library first.** Check `library/index` for room modules, pods, corridor and riser modules, plant-room typicals, preferred products, tested details and lessons before designing anything new. Projects lock the library and standards versions at S0; library updates never overwrite a running project without an impact list and gate approval.
5. **Keep advancing between gates; never ask, always bound.** Missing information becomes `ASSUMED — TBC: <parameter> = <value> (range, affected objects, owner, expiry gate)`. Work that does not depend on the missing item continues; the affected part stays provisional; an assumption is never presented as a final pass. The PD decides at gates only.
6. **Consultants come in last, against a mature package.** Do not contact consultants, certifiers or authorities before S9. At S9 hand over one frozen, complete package (drawings, IFC, calc book, DBR, compliance matrix, PS / SiD registers, spec) and procure a fixed-fee review with defined response rounds under one of the three engagement packages (`references/certification.md`). Statutory engineering responsibilities (QLD RPEQ supervision, NSW DBP, NZ PS1) are met as the region requires, not renamed away.
7. **Design and review use different model families.** The blind re-calculation is done by another family that receives only raw facts, the brief and the applicable standards; a third family arbitrates. Brand is not fixed.
8. **Cite standards only from source text.** Every citation carries standard, year, clause and, where it exists, the digest record id. If the clause text is not in the knowledge base, write `CLAUSE TO CONFIRM`. Key clauses, table notes and exceptions are verified on the source page; extraction agreement between two models is recorded as agreement, not as truth. The code edition, state variations, digest hash and tool versions are written into the brief.
9. **Freeze and change.** Each gate freezes a parameter set. Later changes go through a change request: what changes, which calcs / sheets / models / BQ lines must be rerun, cost and programme impact; the PD approves before regeneration. A freeze is the current traceable baseline, not a promise of no rework; a hard technical FAIL can never be frozen.
10. **Every output self-checks and reports its checks.** Sheet QA overlay, DB consistency, model checks, clash, calc-ID coverage, catalogue integrity. Script success is a data-consistency result, never an engineering PASS.
11. **One thing per sheet, and never economise on sheets.** One level, one system family, one scale per sheet; plant rooms on their own 1:50 sheets; a view over the density threshold (≈ 60 annotated items on A3, ≈ 150 on A1) is split before it is drawn. Annotations are declared, never hand-placed: `scripts/annotate.py` stacks labels in one aligned column per side in target order, anchors leaders on the target outline, routes them through nothing but the target, keeps dimensions on the other sides and falls back to keyed notes. No leader crosses another leader or a dimension line; no text sits on a line or on other text. `python3 scripts/annotate.py check <sheet>` and the embedded overlay count these; a non-zero count is not issued. Drawing counts in the list are planning estimates: the level–sheet–revision matrix, checked against the actual graphics, is the completeness evidence; manifests and badges are only an index.
12. **Every calculation goes into the stage calc book.** `CALC-BOOK_<project>_<stage>_<date>.html` generated from `calcs/` for shared reading; the consultant's signed original calculations are stored as exact immutable revisions linked to the book, and a web update can never alter a signed original. Reviewers read calculations against the frozen manifest.
13. **First principles, then TCO and return, for every design decision.** Strip inherited assumptions, rebuild from what is provably true, compare options on CAPEX, annual net OPEX, hold-period cash flows and TCO; record ΔCAPEX, annual net saving, simple annual return, payback and NPV / IRR when needed. Extra CAPEX is adopted only when simple annual return = annual net saving ÷ incremental CAPEX ≥ 15 % (payback ≤ 6.67 years, added maintenance and replacement inside the net saving; this threshold is not an IRR), or the PD records a non-financial reason. A technical FAIL is never waived by a financial argument.
14. **One project, one growing web knowledge base.** Public browsing needs no login; staff add, revise or attach files through the ProjectBook workbench (or, until it is live, `scripts/catalogue.py`) with the same ADD / REVISE / ATTACH semantics: stable `document_id`, immutable `revision_id` + SHA-256, attachments bound to exact revisions. Technical packages are frozen atomically against a complete revision manifest; "current" is held per use (design / construction / operations) and per scope, never by upload time; drafts never replace endorsed or accepted records; publishing a new effective revision archives the prior one for that use immediately, with permanent history. Gate reviews at G1 / G3 / G4 / G5 and S8 run on frozen packages, at most five rounds.
15. **Technical status vocabulary is fixed.** `PASS` = completed evidence meets the criterion. `FAIL` = technical criterion not met; the PD cannot waive it, only a design change or a valid alternative solution closes it. `NOT CALCULATED` = not yet computed (name the missing input). `TBC` / `ASSUMED` = input unresolved. `N/A` = demonstrably inapplicable, with the reason. Document states are separate facts: draft, AI-reviewed (which layers, which version), consultant-endorsed (who, scope, revision, hash), construction-issued, accepted as-built. A technical PASS, an endorsement, a manufacturing release and a publication are four different facts and never substitute for one another.
16. **Every calculation on the master list is accounted for at every gate — no silent omission.** `templates/calc-templates/calc-master-list.csv` is the company minimum (218 rows: MECH, ELEC, HYD, FIRE, STR, façade and roof incl. fixing spacing, acoustics, thermal outputs, VT, civil, ARC / ID compliance, traffic, construction planning). At each gate `scripts/calc_coverage.py init` writes `calcs/coverage-<stage>.csv` with every row due at or before the stage and the AI answers every row with PASS (calc IDs + evidence), FAIL, NOT CALCULATED (reason, missing input, owner, expiry gate), TBC (owner, expiry gate) or N/A (specific condition + who accepted). `check` must pass before the gate report is written; a blank row, "to be verified manually", "per manufacturer" or "by others" is a defect. Every PASS / FAIL row is a calc page in the format of `templates/calc-templates/calc-page.md`.
17. **Big services are coordinated in 2D before any 3D exists.** At S3 every corridor gets lanes and a ceiling-zone depth budget with the band order structure → fire → ducts → pipes → trays; at S6 every run has a size and top / bottom RL and every large × large crossing (duct ≥ 600 wide or ≥ 400 deep, pipe DN ≥ 100, tray ≥ 450, busway) is registered in `db/crossings.json` with a combined-services section. `scripts/coord_check.py` runs per level; a level with P0 / P1 findings does not get its M / E / H / F layouts issued. The S7 clash run is for what 2D cannot represent, never for the first meeting of a duct and a main (`references/services-coordination-2d.md`).

House rules that also apply: no revision labels on documents while drafting — date only; never show value-engineering dollar values in consultant-facing documents; every China-sourced category needs dual certification (source certificate + NATA / ILAC report to the Australian method + the Australian scheme mark); fire pumpsets, hydrant / sprinkler valves, fire-rated cables, smoke-control fans, essential switchboard sections and all dry fire are local-only; an AI never invents serial numbers, install dates, warranty dates, signatures or test results — unknown is `TBC`.

## Roles

- **PD (project director)** sets the brief, style and systems; decides at gates and on the façade option; handles external contact; may record non-financial reasons but never waives a technical FAIL.
- **AI operator** — one per project of any size. Feeds inputs, runs the stages, reads gate reports, drops review requests and uploads. On towers runs three parallel AI streams (ARCH+ID / STR / MEP+FIRE); the bottleneck is human reading time.
- **Checker** — reads only the high-risk table at each gate, about half a day. Defaults to the PD.
- **PM (project manager)** — named at S0; owns the knowledge-base catalogue, the handover matrix, the monthly exception check (20-minute target) and consultant endorsement registration; acts as Operation Owner until one is appointed.
- **Operation Owner** — named at S0; co-freezes the Handover Baseline; owns `current_operations` after handover.
- **Revit drafting team** — S10: all Revit modelling, families, views, sheets, schedules, tags, dimensions, details, reinforcement coordination and drawing QA, manually, against the frozen IFC / DB / drawings, keeping the element id-map; no automation development is scheduled for this.
- **Procurement** — maintains the product library; issues RFQs from S5; writes vendor handover requirements into RFQ / PO.
- **IT / Dong** — knowledge base, standards ingestion, runner, portal.
- **External** — signing consultants, certifier, authorities: S9 only; contractors and vendors feed construction records after S10.

## How to work a stage

1. Identify the stage and gate from the request. If the project repo exists, read `db/`, `catalogue.json`, the last gate report and open issues before doing anything.
2. Check the library (`references/library-and-repos.md`) for anything reusable; record what was reused and the locked versions.
3. Run `python3 scripts/calc_coverage.py init --stage <S> --carry <previous coverage>` and read the rows due: that is the work list for calculations. Produce the stage outputs by editing the DB and running the generators and check scripts. Calculations go into `calcs/` with calc IDs and one calc page each; drawings are drawn from the generated sheet list one sheet per response and checked; for MEP layouts run `scripts/coord_check.py` per level first; decisions go into `decisions.md`.
4. Run the checks: sheet QA, `coord_check`, `calc_coverage.py check --stage <S> --register calcs/calc-register.csv`, DB consistency. Fix failures in the DB, not in the outputs. Report the counts, including the coverage summary (rows per discipline: PASS / FAIL / NOT CALCULATED / TBC / N/A).
5. Register outputs in the knowledge base (`scripts/catalogue.py add | revise | attach`, or the portal when live) with the fixed sentence: "把任务 X 的新增 / 修改产物加入项目 Y 的原知识库，匹配 document_id，保留所有未改内容；先返回入库草稿链接和影响清单，正式生效按已有 gate 执行。" Nothing is published as current until the gate or release that governs it.
6. Write the gate report from `templates/gate-report.md`: outputs, checks, blind re-calc summary, findings, assumptions with expiry gates, cost movement, decisions this stage, the high-risk table in the mandatory format, open issues by severity, what the PD must decide, the freeze list.
7. Stop at the gate. State plainly what the PD must decide and what stays provisional.

## Output formats that never vary

- **Assumptions**: `ASSUMED — TBC: <parameter> = <value> (<range>; affects <objects>; owner <name>; expires at G<n>)`, in the assumptions list and in the NOTES cell of drawings.
- **Calc register**: `templates/calc-register.csv`, one row per calc, calc ID as the key, status from rule 15. A number on a drawing without a calc ID is a defect.
- **High-risk table** in every gate report: per item — check item / completion evidence and method (calc ID, inputs, clause) / result vs limit and technical status (PASS · FAIL · NOT CALCULATED · TBC · N/A) / gate handling (what closes it, before which release). Never "to be verified manually". FAIL blocks; the PD cannot convert a FAIL to PASS.
- **Drawings**: numbering A/S/M/E/H/F/I (+ C combined, Q façade, N acoustic, T traffic / civil, X thermal, D access, K construction planning) with family blocks per level (`references/drawing-list.md`); text English uppercase; depth at least the HY-0040 benchmark for every system schematic; every sheet carries a manifest JSON and the QA counts; the level–sheet–revision matrix lists which sheet and revision applies to each physical level.
- **Calc book**: `CALC-BOOK_<project>_<stage>_<date>.html` from `gen_calcbook.py`; JSON export appended; blind re-calculation values and differences per calc.
- **BQ**: `BQ (ESTIMATE)` at S6 (ratio rules allowed, labelled) and `BQ (PROCUREMENT)` at S10 or per mature package (actual itemised installation components: bend angles and DN, tees and reducers, flanges / glands / joints, hanger types / spacing / composition / anchors, insulation material and thickness, one tested fire-stopping system and size per penetration; waste, spares, testing and commissioning listed separately; no percentages).
- **Decision record**: `templates/decision-record.md` — context, facts and stripped assumptions, options with CAPEX / annual net OPEX / hold-period cash flows / TCO, ΔCAPEX, annual net saving, simple annual return, payback, NPV / IRR if needed, risk, PD decision.
- **Review round**: `reviews/<task>/round-<n>/` (packet, calls, feedback.json, responses.json) and `issues/issue-register.csv`, written only by `scripts/peer_review.py`; severities P0 blocker / P1 major / P2 minor / P3 suggestion; `issue_id` stable across rounds; states REQUESTED → VALIDATING → FROZEN → REVIEWING → RESPONSE_REQUIRED → CLOSED / HUMAN_REQUIRED.
- **IFC issue**: `templates/issue.schema.json` (`wsg.issue/1`): release id, model SHA-256s, components with IFC GlobalId + DB id, engineering-coordinate anchor with transform snapshot, viewpoint, snapshot, description, status UNTRIAGED → OPEN → READY_FOR_REVIEW → CLOSED / NEEDS_RELOCATION.
- **Manufacturing release sheet**: `templates/release-sheet.md` per procurement package — vendor performance and dimensions, calcs, interfaces, clash / maintenance, peer review, approvals affecting the package, production drawings and BQ at the same revision; without it only RFQ or cancellable capacity reservation, with exit cost recorded.
- **Endorsement record**: `templates/endorsement-record.json` — signer, firm, discipline, date, conditions, document_id, revision_id, SHA-256, scope, covering letter; originals unchanged; a later revision never inherits it.
- **Asset register** and **handover matrix**: `templates/asset-register.csv`, `templates/handover-matrix.csv`; unknown fields `TBC`.
- **EnergyPlus results**: `templates/results.schema.json` (design_cooling_kW, design_heating_kW, annual_kWh, design_day_basis, vendor_duty_check, run_status); the report is `thermal/report.md`, conclusions first; a failed or absent run is reported as such, never as PASS.
- **Gate report**: `templates/gate-report.md`. One report per gate, dated, no version labels; includes decisions this stage and the review-round summary.
- **Language**: drawing text English uppercase; internal reports in the requester's language (Chinese or English, or bilingual); supplier correspondence in Chinese; consultant-facing documents in English.

## Review in one paragraph

Two models reviewing each other share blind spots, so review is four layers, each catching what the previous cannot: deterministic scripts (DB ↔ drawings ↔ model ↔ schedules consistency, code-limit tables, clash, calc-ID coverage, catalogue integrity); blind re-calculation by a second model family that receives only raw facts, the brief and the applicable standards — never answers, code, selections, conclusive drawings or past feedback — and whose independent answer is frozen before the comparison package is opened; LLM review of assumptions, code edition and state variations, buildability, procurement reality, sequence, actual graphics and interfaces (manifests navigate, they do not certify); and a person reading the high-risk table. Findings go into the issue register with severity, owner and closure evidence; a gate closes only with P0 / P1 = 0, technical FAIL = 0 and no expired blocking assumption. The 99 % target is a seeded-defect detection rate validated on independent samples (59 zero-miss samples → 95 % one-sided lower bound ≥ 95 %; 299 → ≥ 99 %), reported as target vs measured with n; it is not whole-design correctness. Details: `references/review-and-gates.md`.

## Certification in one paragraph

Regions decide how the S9 package is prepared and who carries statutory responsibility, not when consultants are engaged. QLD: professional engineering services need an RPEQ or genuine direct supervision by one (an in-house RPEQ can supervise; a final signature is not supervision; "verified" on Form 15 does not replace it). NSW: DBP applies to regulated designs (Class 2 / 3 / 9c); the hotel / motel exemption needs the building to be outside a strata scheme and without serviced apartments — check the conditions, not the label. NZ: the engineer substantively evaluates the design and takes responsibility for the adopted scope (PS1 / PS2 as the BCA accepts). Japan: a kenchikushi holds the statutory design role; ours is an owner's technical package. Three engagement packages — A verify & certify, B adopt & complete, C application support — with ten mandatory contract points, in `references/certification.md`.

## Things that look helpful but are defects

- Hand-editing a generated output and not recording the diff; a manual change to a dimension, load or equipment that is not written back to the DB; a generator overwriting manual detailing silently.
- A calculation "done in the head" without a calc ID and a script or worked formula; a code value typed from memory instead of fetched from the standards digest by record id.
- A calc book that lists what was done but not what was due: a coverage row left blank, answered "to be verified manually / per manufacturer / by others", or marked N/A because the calculation was inconvenient; a NOT CALCULATED row without the missing input, an owner and an expiry gate; a tool that is unavailable in the current environment reported as anything other than NOT CALCULATED.
- A duct and a main that meet for the first time in the S7 clash run; a large × large crossing without a register entry and a section; a layout sheet without RLs at every crossing; a bulkhead added late to rescue an S3 ceiling-zone budget.
- Asking the PD a question that a bounded assumption would have covered; stopping a stage because one input is missing; presenting an assumption as a final pass.
- Emailing or "checking with" a consultant before S9; appointing a consultant early "to be safe"; renaming statutory engineering work as owner's design development to avoid supervision.
- A gate report without the high-risk table; a row without a technical status; a FAIL "accepted" by the PD; a script run presented as an engineering PASS; "to be verified manually".
- Version labels (v1, Rev A) on a document still in draft; dollar VE figures in anything a consultant will see.
- Building MEP in 3D before equipment is selected; freezing unconfirmed vendor data at G4a; releasing manufacturing at G4 or without a release sheet.
- Two levels or two system families on one sheet; a plant room squeezed into a floor plan; a hand-typed leader coordinate; a dimension on the label side; four leaders to four identical cables; a drainage sheet without floor wastes, tundishes and the ORG; a DB schedule that disagrees with the board elevation or lacks cable sizes and directions.
- Treating the drawing-count table as completeness evidence; trusting a manifest or badge instead of the actual graphic.
- A ratio-based BQ presented as the procurement BQ; a design option adopted without a decision record; the 15 % simple-return threshold called an IRR.
- Claiming a portal, viewer or runner capability that is `UNVERIFIED`; showing "AI has received it" when a draft is only saved locally; inventing progress percentages.
- Auto-closing an IFC issue because the component disappeared in the new release (that is NEEDS_RELOCATION); closing an issue on the designer's reply instead of verified change.
- Copying an endorsement to a new revision; altering the bytes of a signed original; marking a design deliverable as accepted as-built; letting upload time decide what is "current".
- Fabricating serial numbers, install dates, warranty dates, commissioning results or signatures.
